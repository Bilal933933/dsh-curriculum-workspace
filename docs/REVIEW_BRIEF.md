# مهمة المراجعة (REVIEW BRIEF)

> اقرأ `AGENTS.md` أولًا، ثم `docs/ARCHITECTURE.md`. هما العقد. لا تقترح ما يخالفهما.

## 1. السياق في سطرين

مشروع شخصي لمعلم لغة عربية: يحوّل كتب المنهج المدرسي من PDF إلى Markdown، يفهرسها، ثم يسترجع منها إجابات **موثقة برقم صفحة** عبر مهارات (skills) تعمل داخل وكيل برمجي.

## 2. ما نريده منك

راجع **الطبقة المنطقية** (`scripts/` + `.agents/skills/` + `meta/` schemas) وأعطِ:

1. **أخطاء حقيقية**: مسار مكسور، شرط خاطئ، حالات حدّية، تعامل مع ترميز عربي، فشل صامت.
2. **هشاشة**: أين ينكسر السكربت على كتاب مختلف الحجم/البنية؟
3. **تكرار قابل للتوحيد**: دوال مكررة بين `convert/` و`retrieval/`.
4. **قابلية الاختبار**: ما الذي يمكن فصله ليعمل بلا بيانات حقيقية؟
5. **مخالفات الدستور**: أي سطر يخالف `AGENTS.md` (§2 قراءة فقط، §5 المصادر والاستشهاد).

**صيغة المخرج المطلوبة لكل بند:**

```
الملف: scripts/....py:NN
المشكلة: (سطر واحد)
الأثر: (ماذا يفسد عمليًا)
الإصلاح: (وصف مختصر + مقتطف)
الخطورة: عالٍ / متوسط / منخفض
الثقة: مؤكد / محتمل (وما الذي يثبته)
```

## 3. ممنوعات

- ❌ لا تقترح تعديل `output/` أو `index/` يدويًا — هما مشتقّان، والتعديل يبدأ من `curriculum_raw/` عبر سكربت.
- ❌ لا تُضف مكتبات بلا سبب مبرَّر في `requirements.txt`.
- ❌ لا تفترض محتوى كتب — انظر `fixtures/`.
- ❌ لا تقترح «أعد كتابة المشروع من الصفر»؛ المطلوب تحسين متفاوت الأثر لا استبدال.

## 4. عيّنة الاختبار

`fixtures/demo_book/` كتاب مصطنع (صفحتان + `toc.yaml` + مدخل catalog مصغّر) يصلح لتشغيل:
`python scripts/retrieval/normalize.py` و`python scripts/retrieval/build_index.py --dry-run` بلا لمس بيانات حقيقية.
